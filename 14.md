# La Revolución del "Spec-Driven Development"
<!-- background: spec.png -->
## El código ya no se improvisa. Se gobierna con planos.

Ya no le pides funciones sueltas a la IA. El flujo de trabajo actual se basa en un ecosistema de especificaciones (.md) que guían al agente en cada paso del camino:
```text
[ Negocio ] + [ Stack ] + [ Análisis ]+ [ Criterio ] + [ Specs QA ]
                                   │
                                   ▼
                       ➔ [ EL AGENTE EJECUTA ]
```
<!-- reveal -->
**¿Qué queremos lograr? (Specs de producto)**
Las reglas básicas del negocio: qué debe hacer la aplicación y cómo debe comportarse para el usuario.

<!-- reveal -->
**¿Cómo lo escribimos? (Specs de lenguaje)**
Las normas de calidad del proyecto: el lenguaje, el estilo y las herramientas que garantizan que el código sea profesional.

<!-- reveal -->
**¿Qué vamos a cambiar? (Specs de análisis)**
El plan de acción: qué partes específicas del sistema vamos a tocar y cuál es la lógica que vamos a añadir.

<!-- reveal -->
**¿Qué debemos evitar? (Specs de criterio)**
La guía experta: los consejos, precauciones y restricciones de diseño para no cometer errores innecesarios.

<!-- reveal -->
**¿Cómo lo verificamos? (Specs de calidad)**
La lista de pruebas: los pasos necesarios para confirmar que el trabajo está bien hecho y listo para funcionar.

> **Nota del presentador:** Haz hincapié en el cambio de rol del programador. "Chicos, fijaos en esto. El trabajo ya no es escribir el if o el for. El trabajo en la empresa actual es saber componer y conectar estas especificaciones. Cuando el agente de IA tiene las Specs aplica todo el conjunto y te genera la funcionalidad entera sin errores. El programador pasa de ser un 'picador de código' a un 'director de especificaciones'."
