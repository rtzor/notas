## El Prompt Estructurado (La receta)

<!-- hide-from: 1 -->
 - **Rol** definido.
 - **Stack** tecnológico concreto.
 - **Requisitos** funcionales y técnicos.
 - **Restricciones** claras.
 - **Gestión de errores** y casos al límite(Edge cases)
 - **Formato** de salida esperado.

<!-- reveal -->
```text
ROL:
Actúa como un desarrollador Frontend Senior experto en UX y rendimiento.

STACK TECNOLÓGICO:
- HTML5, CSS3 con Tailwind (vía CDN) y JavaScript nativo (ES6+).
- Sin frameworks (No React, no Vue). Código modular en un único archivo.

OBJETIVO / REQUISITOS FUNCIONALES:
Crear una interfaz web que tome notas escritas en formato Markdown y las renderice de forma elegante.
- Panel izquierdo: Un textarea para escribir la nota en Markdown.
- Panel derecho: Previsualización en tiempo real del HTML generado.
- Si el usuario escribe "---", debe interpretar que empieza una nueva diapositiva y activar una paginación.

RESTRICCIONES:
- Cero librerías externas para la paginación o el layout, hazlo con JS nativo.
- El diseño debe ser responsive y limpio (look & feel moderno/oscuro).

GESTIÓN DE ERRORES Y EDGE CASES:
- Si el Markdown está vacío, muestra en el panel derecho: "Empieza a escribir para ver la magia...".
- Si el usuario introduce etiquetas <script>, desinféctalas (sanitiza) para evitar ataques XSS,
 mostrando el código como texto plano.
- Si una diapositiva se queda vacía tras un "---",
 no muestres un slide en blanco; descártala automáticamente.

FORMATO DE SALIDA ESPERADA:
- Un único archivo index.html auto-contenido, listo para abrir en el navegador
 con el código JS y CSS incrustado y correctamente comentado.
```

> **Nota del presentador:** Aquí dejas de comparar y pasas a inspeccionar el prompt bueno entero. Léelo por bloques, no línea a línea.
